The fingerprint freezes what the configs do not state. The semantics source is the transformers release named in `museglimmer_manifest.json` `semantics_source`, currently `transformers==5.17.0` `modeling_muse_glimmer.py` (commit `856157a2f3e9594954310df18fdccc31ffddebe9`, `modeling_file_sha256` `e69eb21d6efd815a48499d4d0e4180afda2f443beb441a734d50efc2cf83f975`); line numbers (`L`) refer to that file unless another file is named (`masking_utils.py`, `cache_utils.py`: the same 5.17.0 release).

- **Output gate.** `self_attn.gate_proj` is a bias-free Linear 6656 → 4096 (L321; checkpoint `self_attn.gate_proj.weight` BF16 `[4096, 6656]`). It reads the `input_layernorm` output — the same tensor that feeds Q/K/V (L396–400) — **not** the attention output. It is applied as `attn_output.reshape(B, S, 4096) * sigmoid(gate_proj(x_normed))` after the head merge and before `o_proj` (L367–369): elementwise over 4,096 = 32 heads × 128 channels, not a per-head scalar. Gate GEMM, sigmoid and product run in BF16.
- **Q/K norm.** One shared weightless `MuseGlimmerRMSNorm(eps=rms_norm_eps=1e-5)` (L322), applied per head over the 128 channels of Q and of K (L336–341): FP32 `x · (mean(x²)+eps)^(−0.5)` (L111–114, `pow`, not `rsqrt`), cast back to BF16 (L120). Then `q = q_normed * qk_scale_factor` with `qk_scale_factor = 3.87` (`config.json` L138; L340), multiplied in BF16 after the cast; K is not scaled; the attention kernel scales scores by `head_dim**-0.5` (L301, L362). Net score scale 3.87/√128 = 0.34206. The value 43.7840518911 in this RFC's table (it is not in the model card, and the pinned HF repo ships no `params.json`) is 3.87·√128 — the native-schema value that the HF modular config pre-folds: vLLM's config shim and SGLang's config both default `qk_scale_factor = 43.7840518911`, SGLang rebuilds it from the HF config as `qk_scale_factor * sqrt(head_dim)`, and vLLM's `_muse_glimmer_query_prescale` divides any value ≥ √128 back to 3.87. The placement differs per runtime: HF and vLLM pre-scale Q by 3.87 in BF16 and use 1/√128 in the kernel; SGLang uses a softmax scale of 43.784/128 with no Q pre-scale; Megatron Bridge uses `softmax_scale = 3.87/√128`. Strict mode freezes the HF placement. The checkpoint has no `q_norm`/`k_norm` weights.
- **`post_norm_eps`.** Governs `post_attention_layernorm` and `post_feedforward_layernorm` (1e-8; L381, L383). `input_layernorm` and `pre_feedforward_layernorm` use `rms_norm_eps` (1e-5; L380, L382). All four are `MuseGlimmerTextCenteredRMSNorm`: FP32 `x · rsqrt(mean(x²)+eps) · (1 + w)`, cast to BF16 (L129–137); the checkpoint stores `w`, so the effective scale is `1 + w`. The post-norms sit between the sub-layer output and the residual add (L407–408, L413–414). The final `norm` is the plain form `x · (mean(x²)+eps)^(−0.5) · w` with `rms_norm_eps` (L102–120, L467).
- **Embedding normalization.** `MuseGlimmerTextNormedEmbedding` = BF16 table lookup (`[202048, 6656]`) followed by the weightless `MuseGlimmerRMSNorm(eps=rms_norm_eps=1e-5)` (L438–446, L461–463): FP32 compute, `pow(·, −0.5)`, cast to BF16. No `√hidden_size` multiplier, no weight. The norm is unconditional in the modeling code (`config.json` has no `normalize_tok_embeddings` key).
- **Soft cap.** `logits = lm_head(h)` → `× output_multiplier` (0.19611613513818404 = 1/√26) → `÷ final_logit_softcapping` (20.0) → `tanh` → `× 20.0` (L1165–1172), i.e. `20 · tanh(z · m / 20)`; the multiplier is applied before the cap. The config key is `final_logit_softcapping` (`config.json` L16); `output_soft_cap_temp` is the native-schema name. In the HF reference every step runs in BF16 (the `lm_head` output dtype; Python-scalar ops do not promote). vLLM and Megatron Bridge use the same formula and order. The strict path must declare its own logit dtype and use it on both sides.
- **RoPE.** Default RoPE, `inv_freq = 1/θ^(arange(0,128,2)/128)` → 64 frequencies, `emb = cat(freqs, freqs)` → all 128 channels of every head are rotated (no partial rotary), `rotate_half` layout (L191–219, L241–245). θ = 500,000 from `rope_parameters.rope_theta`; angles, cos and sin are computed in FP32 from `position_ids.float()`, `attention_scaling = 1.0`, then cast to BF16 (L202–212); the rotation itself runs in BF16. Positions are absolute (`past_seen_tokens + arange`, L496–499). `layer_rope_theta[i]` is used only as a boolean: a layer gets RoPE iff `layer_rope_theta[i] != 0` (L522); the non-zero per-layer values are never read (one `rotary_emb`, L468, L515). RoPE is applied after the Q/K norm and the Q scale and before the cache write (L340–349).
- **Local-layer window and eviction.** Mask: `kv_idx <= q_idx and kv_idx > q_idx − 2048` on absolute indices (`masking_utils.py` L81, L100, L139, L510–511). A query at absolute position *p* attends to keys at positions max(0, p−2047) … p: 2,048 keys including itself, 2,047 past tokens. Cache: `DynamicCache(config)` builds a `DynamicSlidingWindowLayer(sliding_window=2048)` for every `sliding_attention` layer (`cache_utils.py` L1237–1241, L1742–1743, L1808–1812; L494); on every `update` it hands the attention the retained keys plus the new chunk, then keeps only the last `sliding_window − 1 = 2047` tokens (`cache_utils.py` L248–263). Eviction is eager (every update, including mid-prefill chunks) and the HF cache retains **2,047** past tokens, not 2,048. `StaticCache` keeps a 2,048-slot ring buffer but exposes the same 2,047 past keys (`cache_utils.py` L521–523, L569–571, L600–622). Megatron Bridge `window_size=(2047, 0)` and SGLang `sliding_window − 1` agree. Global layers use a plain `DynamicLayer`, full causal, `position_embeddings=None` (L522).
- **Projection grouping.** The checkpoint stores four separate attention matrices per layer (`q_proj [4096, 6656]`, `k_proj [256, 6656]`, `v_proj [256, 6656]`, `gate_proj [4096, 6656]`) and separate MLP `gate_proj`/`up_proj` (`[19968, 6656]` each); HF runs them as separate GEMMs (L336–338, L368, L155). Megatron Bridge fuses Q/K/V/gate into `linear_qkv` (interleaving each head's Q and gate rows) and gate/up into `linear_fc1`; vLLM and SGLang fuse Q/K/V into `qkv_proj` (SGLang un-fuses Q/K/V only for quantized checkpoints), keep `output_gate_proj` separate, and fuse gate/up into `gate_up_proj`. The fingerprint pins the checkpoint grouping — four separate attention GEMMs and two separate MLP GEMMs (`OFFICIAL_PROJECTION_GROUPING`) — and fails closed on `qkv_proj`, `qkvg_proj`, `linear_qkv`, `gate_up_proj`, `linear_fc1`.
